Vas a oír "API" en casi cualquier conversación sobre software. Suena técnico, pero la idea viene de la vida diaria.

## La imagen

<ApiWaiter />

**Una API es un mesero entre programas.** Tu app no entra a la cocina de otra empresa. Pide de un menú, el mesero lleva el pedido y el plato vuelve.

| Palabra | En el restaurante | En el software |
|---|---|---|
| **API** | el mesero | la forma en que un programa le pide algo a otro |
| **Documentación de la API** | el menú | la página que dice qué puedes pedir y cómo |
| **Solicitud** (*request*) | tu pedido | lo que tu app pide |
| **Respuesta** (*response*) | el plato | lo que vuelve (datos, o un error) |
| **Endpoint** | un plato del menú | una cosa específica que puedes pedir, como "el clima actual" |

API quiere decir *Application Programming Interface* (interfaz de programación de aplicaciones). Lo puedes olvidar ya mismo: nadie usa el nombre largo.

## Encuéntralas en la vida real

Hay APIs detrás de casi todo lo que hace tu celular. Piensa en tres apps que usaste hoy y adivina a qué APIs llaman. Algunas pistas:

- Un widget del clima le pregunta a una **API del clima**.
- "Iniciar sesión con Google" le pregunta a la **API de inicio de sesión de Google**: *"¿de verdad es esta persona?"*
- Una app de domicilios muestra un mapa de una **API de mapas** y cobra a tu tarjeta con una **API de pagos**.
- Una app con un asistente de IA envía tu mensaje a una **API de IA**, como la de Claude.

<RedFlag title='"la API no funciona, así que puse datos de ejemplo"'>
	A veces una API no responde, y un agente lo "resuelve" mostrando números inventados sin decírtelo claramente. Tu página se ve bien, pero es falsa. Cuando Claude diga que usó datos *de ejemplo*, *de prueba*, *simulados* o *falsos* (en inglés *sample*, *mock*, *placeholder*), detente y pregunta: *"¿Este número viene de la API real en este momento? ¿Cómo lo puedo comprobar?"*
</RedFlag>
