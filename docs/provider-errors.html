Provider errors

Every failure from an AI provider collapses into one variant of the ProviderError taxonomy and renders as one typed card in chat. This page lists each error, what causes it, and how to get unstuck.

Sign-in and credentials

The credential is the problem. Reconnecting the provider fixes it; retrying without reconnecting never does.

ErrorCausePossible fix
Not signed in / unauthorized unauthenticated

Examples: 401 Unauthorized app_session_terminated your session has ended invalid api key

 The provider rejected the credential. The cause field narrows it:
  • no_credentials: this provider was never connected.
  • token_expired: the sign-in lapsed; signing in again recovers it.
  • token_revoked: the provider ended the session server-side (for example Codex kills the ChatGPT session).
  • invalid_api_key: a pasted key the provider rejected.
 Reconnect

The card's Reconnect button opens the right surface for the provider (browser OAuth sign-in, or the API-key dialog), then auto-resumes the turn once sign-in completes. If the message never reached the model, the retry re-delivers it.

Rate and usage limits

The credential is fine; the account hit a limit. The two differ in whether waiting helps.

ErrorCausePossible fix
Rate limited rate_limited

Examples: 429 Too Many Requests rate limit exceeded overloaded, throttled

 A short-window throttle: too many requests per minute. Waiting a moment helps. When the provider names a delay, the card carries retry_after_seconds and counts it down. RetrySwitch model

Wait out the countdown and retry, or switch to another model or provider for the moment.
Out of quota or credit quota_exhausted

Examples: insufficient balance you've hit your usage limit billing hard limit reached

 A billing-period or plan limit: the account is out of credit, or spent its subscription allowance (for example the Codex ChatGPT-plan allowance, or an Anthropic 5-hour session window). Waiting does not help unless the provider gave a reset time (resets_at). Upgrade planSwitch provider

Top up or upgrade on the provider's billing page (the card links it when known), wait for the reset when one is shown, or switch to a provider with remaining quota. Note: opencode returns this as a 401, but it is a billing problem, not a sign-in problem.
Usage limit pauseddormant usage_limit_paused

Examples: you've hit your session limit usage limit ... reset at 3:30pm

 A plan-window limit was hit, historically the Anthropic 5-hour subscription session limit. Retrying now fails; the limit lifts at the reset time (resets_at). The current engine classifies these as quota_exhausted with a reset time, so no backend emits this kind today; the card still renders when an old chat carries it. Switch model

Wait for the shown reset time, or switch to a different provider (each has its own limits). Routines show "Waiting, resumes at HH:MM" and continue on their own.

Model and context

The account works; this specific model or this specific conversation does not.

ErrorCausePossible fix
Model unavailable model_unavailable

Examples: model_not_supported model not found RegionError

 The requested model is not available to this account: not included in the plan (GitHub Copilot Free rejects premium models), preview-gated, deprecated, or restricted in the account's region. In a team space the card names whose personal account lacks it. Use suggested modelPick another model

Switch to the fallback the card suggests (suggested_fallback) or pick any model the plan includes. Upgrading the provider plan also unlocks the original model.
Conversation too long context_overflow

Examples: prompt is too long context_length_exceeded exceed_context_size_error

 The conversation no longer fits the model's context window, so the provider rejected the request outright. The card carries the provider's own numbers (context_window_tokens, prompt_tokens) when it named them. New conversationSwitch model

Start a fresh conversation, or switch to a model with a larger context window and retry.

Transient and infrastructure

Nothing is wrong with the account or the request. Retrying usually works.

ErrorCausePossible fix
Provider had a problem provider_internal

Examples: 500 / 502 / 503 overloaded_error streaming response failed WebSocket closed 1006

 A 5xx or transient failure inside the provider's own infrastructure: overloaded servers, a dropped stream, a closed connection on their side. Not a problem on this computer. RetryCheck status page

Retry after a moment; these usually clear on their own. If it persists, the card links the provider's status page to check for an outage.
Network unreachable network_unreachable

Examples: fetch failed ECONNREFUSED ENOTFOUND ETIMEDOUT

 The provider's API could not be reached at all: no internet, DNS failure, or a firewall, VPN, or proxy blocking the connection. Retry

Check the internet connection, VPN, and firewall, then retry. If the network is fine, check the provider's status page.

Legacy kinds

Declared by the frontend and still rendered when an old chat carries one, but the current in-process engine never emits them. They date from the removed CLI-era engine, where providers ran as spawned processes.

ErrorCausePossible fix
Session could not resumedormant session_resume_missing

Examples: no rollout found corrupt session transcript

 The saved session the provider was asked to resume is gone or unreadable, so it could not pick up where it left off. The runner automatically restarted a fresh session; the card is informational. Try again

Re-send the message; it runs on the fresh session. Earlier context from the broken session is not recoverable.
Malformed responsedormant malformed_response The provider CLI emitted output mid-stream that could not be parsed, so the turn's result is unusable. Retry

Retry the turn; a clean run replaces the broken one.
Could not start the providerdormant spawn_failed The provider CLI process could not start at all: binary missing, or killed by the operating system before it produced anything. Report bug

Nothing user-recoverable; the report bundles the logs that explain the failed launch.
Cancelleddormant cancelled The user pressed Stop. Kept as a distinct kind so the UI can tell it apart from a real failure.

Nothing to fix. Deliberately renders no card, no toast, and no retry.

Everything else

ErrorCausePossible fix
Unknown error unknown No classifier pattern matched. The card shows the first 300 characters of the raw provider message (raw_excerpt) so it is never content-free. Report bug

Use the card's Report bug button; it bundles the recent logs. Any unknown error that repeats gets promoted into a typed variant above (each family is tracked in Sentry by provider and kind).
