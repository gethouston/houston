# Turn credentials speak through the turn token

A pooled turn runs in a single-use E2B sandbox. It gets one access-only provider credential in its envelope and has no control-plane URL or sandbox token, so every path a pod used to keep its credential honest was dead on E2B: revoked-token reports, dead-key reports, mid-turn re-serves and health marks. Each turn now carries a credential channel built from what it already holds: the turn token (`turn.hostToken`), the gateway origin of its claim heartbeat URL, the org and agent from its store prefix, its acting-as token, and the served provider, kind and row scope. The channel (`TurnCredentialChannel` in `packages/runtime/src/auth/turn-credential-channel.ts`) lives on the turn's `ActingContext` (`packages/runtime/src/session/acting-context.ts`), so concurrent turns never share it, and pod mode never has one.

The channel talks only to the gateway's existing pod-credential family, `/v1/pod/credentials/{org}/{agent}/{provider}`. The gateway already authenticates a turn token there while its claim is active, so a token lifted out of a sandbox dies with its turn.

- **Revoked token (DELETE + `x-houston-if-access-sha256`).** The pod's four gates still apply: `token_revoked` only, the provider's words confirm it, the provider is the one this turn was served, and it is an OAuth token whose used digest is known. The compare-and-delete names the token the failed request ran on, never what the file holds now. The turn waits for the report (10 s at most) before its terminal frame, because the sandbox can be torn down right after.
- **Dead legacy Google key.** Checked once per turn on the served credential and reported the same way. The turn still spends one failed request on it. A pod refuses the key before the turn starts.
- **Re-serve (GET).** Turns use `TurnCredentialStore` (`packages/runtime/src/turn/turn-credential-store.ts`) as pi's credential store. Before this, pi's own file store let it refresh an access-only token with an empty refresh token, and the provider's 401 became a false sign-in card. The store masks access-only entries from pi's refresh and re-serves near expiry. It allows one fetch in flight per provider and waits 30 s before trying again. A marked not-connected 404 writes nothing.
- **Health mark (POST).** A bad credential (`token_revoked` or `invalid_api_key`) posts `needs_reconnect`, and quota exhaustion posts `out_of_credits`. Other auth causes post nothing: a `token_expired` 401 after a failed re-serve, an `unknown` blip or an org policy block says nothing about the stored row. Each mark names the digest of the token the turn's requests last ran on, so after a mid-turn re-serve it names the re-served token, not the first one. The gateway stores it in `gateway.credential_health_marks` only while the stored token still has that digest. Triggers on both credential tables clear the mark on any refresh, login, adoption or sign-out. An `out_of_credits` mark also ends at its reset time. A clean turn posts `connected` only when the dispatch told it a mark exists, so successful turns cost nothing.

The AI Models view no longer trusts the `health` a pod captured. The gateway computes it: a missing credential is `not_connected`, or `needs_reconnect` when the gateway signed it out. A stored one is its live mark, otherwise `connected`. An awake pod's own live answer is still passed through.

The Claude CLI reads its token once, when it starts. For `anthropic` only, the dispatcher asks the serve for a token that outlives the turn ceiling, and the serve refreshes before handing it over. With Anthropic's 8 h tokens, a credential refreshes about every 4 h instead of every 8 h. Providers with shorter-lived tokens keep the 10-minute skew. If a refresh still returns a token shorter than the ask, the gateway remembers that until the token expires and uses the 10-minute skew in the meantime, so no serve refreshes every time. A refresh token the longer ask finds dead does not sign the person out early: the stored token is served until 10 minutes before it expires, and only then does the usual sign-out run.

A pooled turn keeps two per-conversation memories as small files in `sessions/<conversationId>/`, the one folder a claimed turn both downloads and uploads: Codex terse refusals (`codex-refusals.json`, 30-minute TTL) and the integrations reconnect card shown once (`reconnect-offered.json`). Both backends reach the files through the conversation id, and the Claude bridge carries no pi session context. A pooled routine reset deletes the backend session files but keeps these. Only pooled turns write them: a standing pod and the desktop keep the in-memory memories they had before, and their routine reset still clears the session folder, so their files stay unchanged. The reconnect file has no TTL, which matches the pi transcript scan: once per conversation.

## Considered Options

- **A new turn-grant route family for credentials.** It would duplicate the pod-credential routes the turn token already reaches, with the same compare-and-delete and refresh-on-serve. Rejected.
- **The follower reports from the `provider_error` frame.** The gateway would have to know which token the failed request used, which only the worker knows once a turn re-serves mid-turn. Rejected.
- **Health marks as columns on the credential rows.** Each credential write path would have to clear them, and they would sit next to secrets. A side table cleared by triggers heals on every write path, including old replicas. Chosen.
- **Scanning the conversation file for the reconnect marker.** Only the newest archive segments are hydrated, the file can be several MB, and compaction can drop the marker. Rejected.

## Consequences

- Cloud deploys first: migration 115 creates the marks table, and the dispatch starts sending `scope`, `health` and the Claude validity. A new worker on an old gateway reports with scope `team`, which is right for an org row, and a missed compare on a personal row is a no-op. Its health POST gets a 404 and is logged.
- On E2B a Codex refusal is remembered per conversation, not per account.
- Each dispatch serve does one extra indexed read of the marks table.
